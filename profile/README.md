## What this organization is

TheHubs is our engineering organization on GitHub. Each hub owns its own products,
its own roadmap and its own repositories. **This organization is for everything else** —
the transversal work that belongs to no hub in particular but serves all of them.

If a piece of code, tooling or documentation is useful across hubs, it lives here.

## What you'll find here

- **Shared tooling** — CLIs, scripts and developer utilities used across teams.
- **Platform & automation** — reusable workflows, actions, templates and CI building blocks.
- **Libraries & SDKs** — common packages that more than one hub depends on.
- **Documentation & standards** — engineering guidelines, conventions and reference material.
- **Experiments & prototypes** — spikes and proofs of concept that don't yet have a home.

## What does *not* belong here

Anything owned end to end by a single hub. If exactly one hub builds it, runs it and
would be the only one affected by a change, it belongs in that hub's own space — not here.

## Conventions

- Every repository ships a `README.md` explaining what it is, how to run it and who owns it.
- Ownership is explicit: name a team or a maintainer, so nothing becomes orphaned.
- Changes land through pull requests — never pushed straight to the default branch.
- Keep repositories focused. When something grows into a hub's product, move it there.

## Getting started

Browse the repositories below. Each one documents its own setup and contribution flow.
If you're unsure where a new project should live, ask before creating the repository —
choosing the right home up front is much cheaper than moving it later.
